## Import-health round (the "not my problem" challenge)
- Trigger: the operator asked whether the rules say to leave a SyntaxError because it is not mine. They do not (active.md scope: "fix all safe issues"). Layers found behind `plugin_permissions.py`: repeated `description=` (11 blocks) -> `builtins.dict()` unimported -> `get_permission_manager()` missing -> `request_obj` vs `request` -> misspelt `perms` -> comprehension without outer loop -> `PermissionRequest.request_id` never stored -> `PermissionAuditLog.granted_by` missing -> `_stats`/`get_statistics()` never implemented (STOP: new behaviour) -> export dict vs import list mismatch (STOP).
- Method that worked: (1) `compile()` over every tracked .py, (2) one-process import of every `src` module with a SIGALRM guard, grouped by root-cause message, (3) `ruff --select F821` for undefined names, (4) a relative-import resolver: for each unresolved `from .x import`, try other depths and only fix when EXACTLY ONE other depth resolves to an existing module (22 fixes, 0 guesses), plus unique-basename search for moved modules, verifying the imported names exist in the target.
- Stopping rule used: fix when the answer is determined by the filesystem or by obvious intent at several call sites; stop and flag when a class/field would have to be designed (AbortDecision & co, StealthSettings.webgl_protection, ITelemetryIntegration, statistics).
- Mistakes on the way, caught: my first "does the test catch the old bug" check grepped for lowercase words and proved nothing (redone by exit code); a first regex for Depends bound the accessor at import time and would have broken the repo's own patch-based tests (switched to a late-binding lambda and verified both behaviours); the global `compileall src tests` check kept failing on a file outside the scope I'd touched — which is how I should have found the original error in the first place.
- Regression check: `tests/unit` run on a clean worktree of the previous commit AND on the new tree (separate worktree so the live scrape's files stayed untouched); both stall on the same subprocess-wait test, so a per-test timeout was added. Result: before 755 passed / 129 failing, after 762 passed / 130 failing; the one extra failure (`test_is_adaptive_enabled_convenience_function`) is environmental — the baseline code fails it identically with the same local `data/adaptive.db`. The first two comparison attempts were useless (non-verbose output parsed log lines as test names; a global hang burned 40 s per test) — the `-v` + `--timeout=8` run is the valid one.
- Live verification (paced run, 14:03Z): see ADR-30 addendum. Drop duration ~30 min. The persisted rest from the earlier (pre-fix) run correctly blocked the first launch attempt for ~10 min.
