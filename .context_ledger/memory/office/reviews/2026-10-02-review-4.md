# Session 50, later rounds — import health, a clean live run, and what the "empty" ids were (2026-10-02)

Ada (S448). After the open-items round (review-3) the operator asked me, in turn, to find out why the hosts block us, to stop describing the way in as one country, and — when I left a syntax error as "not my change" — whether the rules say to leave things that are not mine. They do not; this report covers what that led to. Decisions are in ADR-30 (addenda) and ADR-31.

## Why the hosts dropped us — and a clean run once we stopped doing it

The drops were a per-source-address penalty: one request through another allowed-country connection reached a host that was dropping this machine. They lasted about 30 minutes after a burst of roughly 20 requests a second. After the penalty expired I ran the scraper once with the fixes from the previous round (3 requests a second, one pooled connection, a shared rest period): about 500 requests' worth of work with no retries, no rests and no drops, and every host still accepted connections afterwards. The stats ids that had resolved "0 of 37" while we were blocked resolve fine now: 10 of 21 new events and 128 of 150 stored ones.

## What the "empty" ids were

For days about four in five discovered ids never became events and I could not say why. Sampling them settled it: they are season-long outright markets ("NBA 2026/27 MVP", "Regular season"), single-participant listings with hundreds of markets, plus the generic "Home (Points) / Away (Points)" placeholders. All 370 stored matches have a second participant in the league list, so discovery now skips entries without one (127 of 497 ids) before making a request for them — a quarter of every run's traffic, and `--skip-processed` can finally reach "nothing left to fetch".

## Import health — the larger finding

I had found a `SyntaxError` in `plugin_permissions.py` and logged it as someone else's. The operator pointed out that the standing scope here is to fix safe issues. Looking properly turned up about 100 of 756 modules under `src/` that could not be imported at all (so navigation, the selector dashboard API, telemetry storage and reporting, the plugin permission system and parts of resilience could never have run), for around 25 reasons: names used without imports, relative imports with the wrong number of dots, classes defined but not exported, a dataclass field order Python rejects, a repeated keyword argument, and dashboard routes that declared a service object as a web query parameter. I fixed everything whose answer was determined by the filesystem or by obvious intent at several call sites, with tests, and stopped where a class or field would have had to be invented. 13 modules remain unimportable, each listed with its reason in a test that fails if a new module breaks or a listed one starts working. The adaptive dashboard API now starts and answers requests.

Importable is not the same as correct. The permission module needed three more layers of fixes before request, approve and export worked, and still has unimplemented statistics and an import/export format mismatch. The dashboard API's own integration tests, uncollectable before, now run and mostly fail because they call routes the app never mounted. `tests/unit` has many failures that predate my changes and a test that hangs forever on a subprocess wait.

## Other changes

The wording about egress is now neutral everywhere (docs, scripts, skin files, tests, the ledger): any allowed-country connection a site has not penalised works; where a tunnel exits is incidental.

## What is still open

The backlog holds the rest, High first: the missing abort-handling classes (6 modules), the `StealthSettings` field mismatch, the selector integration package that does not exist, the permission module's remaining defects, the stale dashboard integration tests, 78 latent undefined names inside function bodies, and the pre-existing `tests/unit` failures and hang. Operator-owned: rotating the proxy password and deciding whether linebet is worth supporting.

## Did any of this break anything?

I ran all of `tests/unit` on a clean copy of the previous commit and on the new tree: 755 passed / 129 failing before, 762 passed / 130 failing after. The seven extra passes are the new tests. One test is in the "failing only after" set, but it is not caused by the change: `test_is_adaptive_enabled_convenience_function` reads a local, untracked `data/adaptive.db` (dated July 27, with `basketball` enabled) while claiming to use an in-memory database, and the old code fails it identically when given the same file. It is a test-isolation problem, recorded in the backlog. The betb2b, security and profile suites pass.
