# Windows gates pass again; the product tree is clean of ledger terms

Achieng (S002), 2026-10-03, Lameck-Windows — a two-question session after the
core 2.0.4 / new-office pull: does the Windows gate pass now, and is any product
code carrying ledger vocabulary.

## 1. The gate: fixed, and verified through both runners

It did **not** pass as pulled — core 2.0.4 does not translate the registry's
POSIX interpreter path, so `ledger-gates run pre-commit` still failed 127 on
this box. The fix lives in the project-owned registry, whose single line must
work on macOS (`.venv/bin/python`) and Windows (`.venv/Scripts/python.exe`).

Rejected along the way, with evidence: a bare `sh tools/gates/pytest.sh` line
(`sh` is not on a clean Windows PATH — Git for Windows puts only `Git\cmd`
there; verified against the machine+user PATH), an inline conditional (`;`
inside a `git -c alias.…` value is treated as a comment by git — the run
silently lost half the command), and dropping the explicit commands for
discovery (it runs bare `python -m pytest`, which is the wrong interpreter on
both platforms).

Shipped: a committed launcher `tools/gates/pytest.sh` (picks the interpreter
the venv actually has, passes extra args through, exits 127 with a plain-word
message when there is no venv) invoked as

    git -c 'alias.ledger-gate=!sh tools/gates/pytest.sh' ledger-gate

`git` is on the PATH in both agent shells, and a `!` alias runs through git's
own bundled shell — verified on a simulated clean Windows PATH, including that
`sh` resolves *inside* the alias while it does not in PowerShell.

Verified end to end:

- `sh .context_ledger/core/bin/ledger-gates run pre-commit` → **PASSED**
- `powershell -NoProfile -ExecutionPolicy Bypass -File …/ledger-gates.ps1 run pre-commit`
  (exactly what `ledger-gates.cmd` runs) → **PASSED**
- `sh tools/gates/pytest.sh -k no_such_test` → exit 5, so a failing suite
  cannot pass the gate silently
- 283 tests, all dots (the summary line is suppressed on this platform; exit 0)

The Mac is unaffected: the same registry line reaches its `sh` and
`.venv/bin/python`. `*.sh` was pinned to LF in `.gitattributes` so a Windows
checkout cannot corrupt the script.

## 2. Product-code ledger vocabulary: none outside the entry points

`ledger-mem lint --tree`: **23 hits, all of them in `AGENTS.md` (13) and
`CLAUDE.md` (10)** — the two managed entry-point files that must name the
ledger directory they route agents to, regenerated from core templates on
updates. **Zero hits in `src/`, `tools/`, `tests/`, or `docs/`**; no ADR numbers
or backlog IDs either. The known upstream limitation (the tree sweep does not
exempt the managed entry points) still stands and is the only reason the tree
sweep exits non-zero.

The sweep did catch one real leak: the loader script written during this
session cited the registry's path in a comment. Stripped — the comment now says
"the project's gate-command registry" in plain words. The staged-diff lint is
clean.
