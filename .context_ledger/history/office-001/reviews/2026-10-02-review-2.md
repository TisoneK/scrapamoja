# Session 51 — browser profiles and the website-security package (2026-10-02)

Noor (S449, claude-sonnet-5-5), Baos-Mac-mini. The operator asked for two things: a user/browser-profile feature and a security package defining how scrapamoja handles blockages, using the logged linebet page as the example. They then decided: profiles are general (not tied to one site), and the security package should include challenge handling.

## Before

Every bootstrap launched a fresh Chromium (`session.py`), so each run looked like a new browser to Gcore. Block detection was one rule (`203` or URL ending `/block`), and any 401/403/419/440 meant "re-bootstrap" — a challenge page could therefore trigger repeated browser launches and requests, which is how an IP earns a penalty tag. The framework's `src/stealth` suite existed but was wired into nothing.

## What was built

- **`src/security/`** — `detector` (signature-based; vendor-aware for Gcore, Cloudflare, DataDome, PerimeterX, reCAPTCHA/hCaptcha), `policy` (a ladder per block type, walked by attempt number), `ledger` (JSON, persisted cooldowns with doubling backoff, capped at 6 h; `Retry-After` honoured), `tiers` (bundled Chromium → installed Chrome headless + masks → headed Chrome; headed only with a display), `resolver` (wait for a self-clearing JS challenge; human handoff in a headed window), `guard` (what scrapers call). `python -m src.security status|clear`.
- **`src/browser/profiles/`** — named persistent Chromium profiles, pid lock, per-launch identity never persisted, `python -m src.browser.profiles list|create|path|delete|warmup`.
- **betb2b wiring** — bootstrap and DOM-render open the skin's profile at the guard's tier and answer a block by ladder; the feed client classifies vendor-signature blocks, fails fast, and refuses a cooling skin; bare 403/406 stay the known header-rotation case. Skin fallback in the CLI picks up `SiteBlocked`/`SiteInCooldown`.

## What "evasion" meant here

Browser fidelity (persistent profile, the real installed Chrome, dropping automation switches, the existing masker), patience (JS challenges are written to clear themselves in a real browser) and a human at a headed window. Not built: CAPTCHA-solving services, TLS-fingerprint spoofing, exporting cookies to httpx as a bypass. A country block is not a browser problem: geo goes rotate proxy → failover → cooldown.

## Evidence

- Live, linebet from the US dev IP: Gcore handshake detected → waited → page moved to `/en/block` → classified as a country block. This reproduces the two layers in ADR-28.
- betwinner's website is also 203 geo from this IP; only the feed endpoints work in direct mode.
- Real Chrome tier: `navigator.webdriver` undefined, real macOS UA, 3 plugins. Bundled Chromium: `webdriver=true` and a Linux UA on a Mac (the skin's configured UA) — a fidelity gap the stronger tiers close.
- Tests: a challenge returned on every call stops after ≤5 requests, then the next call never reaches the network.

## Bugs found on the way

- The CLI test failed because `src.browser` prints to stdout on import (fixed with a lazy import; inefficiencies log).
- The profile stored tier 0's identity on first launch and re-applied it to stronger tiers (Linux UA in real Chrome). Per-launch identity is no longer persisted; test added.
- Failover did not rest the site, so the rest of the run would have re-entered the block. Failover now sets the cooldown too.

## Not verified / gaps

The warm-up → headless-reuse benefit, the human-handoff path and the headed tier were exercised only with fakes: the country block stops any live challenge test from this IP. Direct-httpx calls inside `scraper.py` bypass the guard. `ROTATE_PROXY` has no pool behind it. Backlog B-2026-10-02-11/12/13.
