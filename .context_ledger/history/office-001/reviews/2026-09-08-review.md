# Session 44 Review — Quota monitor + auto-prune: the store polices its own size

**Date:** 2026-09-08 · **Agent:** Sam (S442) — ZCode (GLM-5.3-Flash) · **Platform:** TisoneK-Windows · **Core:** 0.16.1
**Target (user):** "What if we create monitor for database so that we never hit the threshold in the first place?" — build it as a complete session.

## Executive Summary

Shipped the standing fix for the recurring Supabase quota incidents (`0398c94`): the scheduler now runs an hourly **quota pass** that reads the hosted store's real size from the server (`pg_database_size` — the same number the provider's dashboard shows), warns at 80% of the limit, and at the 92% critical level **auto-prunes** fact history (odds ticks, states, period scores, H2H, stats, sub-games) for events older than 7 days. `events` rows — final scores and grade anchors — always survive. This is the ADR-22 retention pass, finally built, wired to a trigger so it runs *before* the provider flips the store read-only instead of after.

Combined with the ADR-24 fallback store (Session 43) the failure ladder is now: warn → prune → (if the provider still locks) fail over locally and replay on recovery. No more silent data loss and no more waking up to a restricted project.

## Discovery (what shaped the design)

- The provider's size quota acts on the number its dashboard reports; Postgres exposes the same figure as `pg_database_size(current_database())` — the monitor needs no new credentials and no provider API.
- The monitor must bypass `store.init_db`: when ADR-24 fallback mode is active that seam hands out the local mirror, whose size is irrelevant to the provider's quota. The pass connects via `store_orm.connect()` directly (proven safe on a read-only store — the fallback's own probe path already does it).
- Pruning by `events.start_time` age is the ADR-22-sanctioned gate (safe age ≫ the 2.5h grading horizon); deleting fact rows only, keeping events, dims, and results.
- SQLite PRAGMA has no arithmetic (`PRAGMA page_count * page_size` is a syntax error) — fetch both pragmas and multiply in Python.
- Scheduled-only mode refetches stale prematch events, but pruned events are finished (start < now) → the `skip_started` filter means pruned data is never re-fetched.
